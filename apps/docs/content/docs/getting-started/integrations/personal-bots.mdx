A bot connection gives one personal bot its own API key. The key can only use the parts of the gateway you allow, and the dashboard shows the exact config to paste into the bot. Everstack does not host or run the bot: it keeps running wherever you run it today.

## What a bot key can and cannot do

A bot key can:

- Call the surfaces you enabled for that bot, and nothing else. A request to any other surface is refused.
- Be replaced with a new key, or removed, from the Bots page at any time.

A bot key cannot:

- Sign in to the dashboard or manage the gateway. Bots, keys and settings are managed only from a signed-in dashboard session.
- Use a surface you did not enable. To change what a bot can use, edit the bot.

Each bot has exactly one key. The key does not appear in the API keys list; manage it from the Bots page.

## Surfaces

| Surface | In the dashboard | What the bot does | Endpoint |
| --- | --- | --- | --- |
| `inference` | Models | Uses the gateway as its model provider | `/v1` (OpenAI-compatible), `/v1/messages` (Anthropic-compatible) |
| `mcp` | Tools | Calls the tools this gateway exposes | `/mcp` (Streamable HTTP) |
| `telemetry` | Traces | Sends OpenTelemetry traces and logs | `/v1/traces`, `/v1/logs` (OTLP over HTTP) |
| `a2a` | Agents | Calls your published Everstack agents | `/a2a/agents/<agentId>` |

Bots send the key as `Authorization: Bearer <your bot key>` on `/v1`, `/mcp`, the OTLP endpoints and A2A. On `/v1/messages`, Anthropic clients send it either as `x-api-key` or as a Bearer token, depending on the client and its SDK version. All endpoints are on the gateway origin, the same address you use for the dashboard.

For A2A, the gateway serves both the legacy JSON-RPC binding (`message/send`) and A2A 1.0 (`SendMessage` with the header `A2A-Version: 1.0`). Replies are synchronous: the call returns when the agent run finishes. There is no streaming and no task polling.

Hosted bots (Grok Bot, Meta Muse) can use Tools only. Grok Build can use Models and Tools.

## Connect a bot in the dashboard

<Steps>

<Step>
### Open the Bots page

Go to **Gateway → Bots** and select **Connect a bot**.
</Step>

<Step>
### Choose the type, name and surfaces

Pick the bot type, give the connection a name, and check what it may use. Models, Tools and Traces are on by default where the bot supports them; Agents is off.

Optionally set a **Rate limit** in requests per minute: a whole number from 1 to 100,000. It counts every request the bot key makes, across all its surfaces. Leave it empty for no bot-specific limit. You can change or clear it later with **Edit**.
</Step>

<Step>
### Copy the key and the config

The next screen shows the key once, with the config for that bot filled in: this gateway's URL, the key and, if you pick one, a model. Copy what you need before you close it. You will not see the key again.
</Step>

<Step>
### Paste the config into the bot

Apply it as described for your bot below. The bot shows as connected after its first call.
</Step>

</Steps>

Later, **Setup** on a bot shows the same config with `<your bot key>` in place of the key.

## Usage and traces per bot

Each row on the Bots page shows when the bot was last seen, how many calls its key made in the last 30 days, and its rate limit if you set one. Hover the call count to see it split by surface (Models, Tools, Traces, Agents). Last seen updates at most once a minute. A bot that has never called shows no count.

Traces, logs and metrics a bot sends with its key carry the resource attribute `everstack.api_key_id`, set by the gateway to the bot's key id. For a bot with Traces enabled, **Setup** shows that value with a copy button. Making a new key changes the value and starts the 30-day count again from zero.

## Configuration by bot

Every config below was checked against the bot's source or official docs. Replace `https://your-gateway.example.com` with your gateway's address, `<your bot key>` with the key, `<model>` with a model id from the Models page, and `<agent id>` with a published agent. Where a setting name could not be confirmed, the guide lists the values to enter instead of a config.

Configs that use `/v1/messages` are marked as Anthropic-compatible alternatives; the OpenAI-compatible provider is the default.

### OpenClaw

- Settings: `~/.openclaw/openclaw.json` (JSON5).
- Apply: OpenClaw watches the file and applies most changes on its own. Restart it after changing `channels.a2a`. After a rejected key it pauses the provider for about a minute, so a new key can take that long to start working. Restart OpenClaw after a new key: models and tools pick it up on their own, but trace export can stay off until a restart.

<Tabs items={["One file","Models","Tools","Traces","Agents"]}>

<Tab value="One file">

Merge these keys into your existing file.

```json5
{
  models: {
    providers: {
      everstack: {
        baseUrl: "https://your-gateway.example.com/v1",
        apiKey: "<your bot key>",
        api: "openai-completions",
        models: [{ id: "<model>", name: "<model>", input: ["text"], contextWindow: 128000, maxTokens: 8192 }],
      },
    },
  },
  agents: { defaults: { model: { primary: "everstack/<model>" } } },
  mcp: {
    servers: {
      everstack: {
        url: "https://your-gateway.example.com/mcp",
        transport: "streamable-http",
        headers: { Authorization: "Bearer <your bot key>" },
      },
    },
  },
  plugins: { entries: { "diagnostics-otel": { enabled: true } } },
  diagnostics: {
    enabled: true,
    otel: {
      enabled: true,
      endpoint: "https://your-gateway.example.com",
      protocol: "http/protobuf",
      headers: { Authorization: "Bearer <your bot key>" },
      traces: true,
      metrics: true,
      logs: false,
    },
  },
  channels: {
    a2a: {
      enabled: true,
      peers: {
        everstack: {
          token: "<a secret of your choice>", // required by the schema even for outbound-only peers
          url: "https://your-gateway.example.com/a2a/agents/<agent id>",
          outboundToken: "<your bot key>",
        },
      },
    },
  },
}
```

</Tab>

<Tab value="Models">

**OpenAI-compatible provider**

```json5
{
  models: {
    providers: {
      everstack: {
        baseUrl: "https://your-gateway.example.com/v1",
        apiKey: "<your bot key>",
        api: "openai-completions", // or "openai-responses" for /v1/responses
        models: [
          { id: "<model>", name: "<model>", input: ["text"], contextWindow: 128000, maxTokens: 8192 },
        ],
      },
    },
  },
  agents: { defaults: { model: { primary: "everstack/<model>" } } },
}
```

- Set `contextWindow` and `maxTokens` to the real limits of your model; the numbers shown are editable defaults.

**Anthropic-compatible provider (alternative)**

```json5
{
  models: {
    providers: {
      "everstack-anthropic": {
        baseUrl: "https://your-gateway.example.com", // no /v1: the Anthropic client appends it
        apiKey: "<your bot key>",
        api: "anthropic-messages",
        models: [{ id: "<model>", name: "<model>", input: ["text"], contextWindow: 200000, maxTokens: 8192 }],
      },
    },
  },
  agents: { defaults: { model: { primary: "everstack-anthropic/<model>" } } },
}
```

</Tab>

<Tab value="Tools">

**MCP server**

```json5
{
  mcp: {
    servers: {
      everstack: {
        url: "https://your-gateway.example.com/mcp",
        transport: "streamable-http",
        headers: { Authorization: "Bearer <your bot key>" },
      },
    },
  },
}
```

- Keep `transport: "streamable-http"`: without it OpenClaw uses SSE, which the gateway does not serve.
- Do not set `auth: "oauth"`, or OpenClaw ignores the Authorization header.

**Or add it with the CLI**

```bash
openclaw mcp set everstack '{"url":"https://your-gateway.example.com/mcp","transport":"streamable-http","headers":{"Authorization":"Bearer <your bot key>"}}'
openclaw mcp doctor --probe
```

</Tab>

<Tab value="Traces">

**Install the telemetry plugin**

```bash
openclaw plugins install @openclaw/diagnostics-otel
```

- Without the plugin OpenClaw accepts the config but exports nothing.

**OpenTelemetry export**

```json5
{
  plugins: {
    entries: { "diagnostics-otel": { enabled: true } },
  },
  diagnostics: {
    enabled: true,
    otel: {
      enabled: true,
      endpoint: "https://your-gateway.example.com", // OpenClaw appends /v1/traces, /v1/metrics, /v1/logs
      protocol: "http/protobuf",
      serviceName: "openclaw",
      headers: { Authorization: "Bearer <your bot key>" },
      traces: true,
      metrics: true,
      logs: false,
    },
  },
}
```

- `diagnostics.otel.endpoint` is a base URL: OpenClaw appends `/v1/traces`, `/v1/metrics` and `/v1/logs` to it.
- If your config already has `plugins.allow`, add `"diagnostics-otel"` to that list.

</Tab>

<Tab value="Agents">

**A2A peer for an Everstack agent**

```json5
{
  channels: {
    a2a: {
      enabled: true,
      peers: {
        everstack: {
          token: "<a secret of your choice>", // required by the schema even for outbound-only peers
          url: "https://your-gateway.example.com/a2a/agents/<agent id>",
          outboundToken: "<your bot key>",
        },
      },
    },
  },
}
```

- Address messages to `a2a:everstack`.
- OpenClaw gives up on an outbound A2A call after 30 seconds, so longer agent runs fail on its side.

</Tab>

</Tab>

<Tab value="Tools">

**MCP server**

```yaml

  everstack:
    url: "https://your-gateway.example.com/mcp"
    headers:
      Authorization: "Bearer <your bot key>"
    enabled: true
    timeout: 300
    connect_timeout: 60
```

- Leave `transport` unset: a bare `url` uses Streamable HTTP.

</Tab>

<Tab value="Traces">

**Install the hermes_otel plugin**

```bash
hermes plugins install hermes_otel
hermes plugins enable hermes_otel
```

- Hermes itself exports only health data; run traces need the community `hermes_otel` plugin.
- Restart Hermes after enabling it (`hermes gateway restart` when the gateway is running).

**~/.hermes/hermes_otel.yaml**

```yaml
# ~/.hermes/hermes_otel.yaml
backends:
  - type: otlp
    name: everstack
    endpoint: "https://your-gateway.example.com/v1/traces"
    headers:
      Authorization: "Bearer <your bot key>"
```

- `endpoint` is the full traces URL.

</Tab>

### ZeroClaw

- Settings: `~/.zeroclaw/config.toml` (or the directory in `ZEROCLAW_CONFIG_DIR`).
- Apply: Reload with `/admin/reload` or restart the daemon. A standalone `zeroclaw gateway start` needs a restart, and MCP grant changes need a new session.

<Tabs items={["One file","Models","Tools","Traces","Agents"]}>

<Tab value="One file">

Merge into your existing file; TOML allows each table header only once.

```toml
schema_version = 4

[providers.models.custom.everstack]
uri = "https://your-gateway.example.com/v1"
api_key = "<your bot key>"
model = "<model>"

[agents.default]
enabled = true
model_provider = "custom.everstack"
risk_profile = "default"
mcp_bundles = ["everstack"]

[risk_profiles.default]

[[mcp.servers]]
name = "everstack"
transport = "http"
url = "https://your-gateway.example.com/mcp"
headers = { Authorization = "Bearer <your bot key>" }

[mcp_bundles.everstack]
servers = ["everstack"]

[observability]
backend = "otel"
otel_endpoint = "https://your-gateway.example.com"
otel_service_name = "zeroclaw"

[observability.otel_headers]
Authorization = "Bearer <your bot key>"

[a2a.client]
enabled = true

[[a2a.client.peers]]
name = "everstack"
base_url = "https://your-gateway.example.com/a2a/agents/<agent id>"
token = "<your bot key>"
```

</Tab>

<Tab value="Models">

- The agent's `model_provider` picks the provider, and the model comes from that provider entry.

**Anthropic-compatible provider (alternative)**

```toml
[providers.models.anthropic.everstack]
uri = "https://your-gateway.example.com"
api_key = "<your bot key>"
model = "<model>"
```

- To use it, set `model_provider = "anthropic.everstack"` in `[agents.default]`.

</Tab>

<Tab value="Tools">

- The `mcp_bundles` grant is required: an agent without it connects to no MCP server.

</Tab>

<Tab value="Traces">

- Needs a ZeroClaw build with the `observability-otel` feature (or the `all-features` image); without it, export is silently off.
- `otel_endpoint` is a base URL: ZeroClaw appends `/v1/traces`, `/v1/metrics` and `/v1/logs`.

</Tab>

<Tab value="Agents">

- ZeroClaw calls agents with A2A 1.0 only and reads the agent card at the peer URL first.

</Tab>

## Let Everstack agents call a bot

The Agents surface covers the other direction: the bot calling Everstack. For Everstack agents to call the bot, the bot must serve A2A itself, and the gateway needs a saved connection to it.

1. Turn on the bot's A2A server (see below) and make it reachable from the gateway.
2. In **Gateway → A2A → Remote agents**, add a remote agent with the bot's endpoint, protocol and bearer token.
3. In **Gateway → Bots**, edit the bot and pick that remote agent. The link shows which saved connection reaches this bot.

**OpenClaw** serves A2A through its `a2a` channel:

```json5
{
  channels: {
    a2a: {
      enabled: true,
      advertisedUrl: "https://your-bot.example.com",
      peers: {
        everstack: { token: "<a secret you choose>" },
      },
    },
  },
}
```

Save the remote agent with endpoint `https://your-bot.example.com/a2a/v1` and the same secret as its bearer token. OpenClaw accepts both `SendMessage` and the older `message/send`. Restart OpenClaw after the change, and make sure its port (18789 by default) is reachable from the gateway.

**ZeroClaw** publishes an agent over A2A 1.0:

```toml
[a2a.server]
enabled = true
public_base_url = "https://your-bot.example.com"

[agents.default.a2a]
published = true
```

Save the remote agent with endpoint `https://your-bot.example.com/a2a/default` and protocol A2A 1.0. ZeroClaw refuses the legacy binding. The bearer token is a ZeroClaw pairing token, which you get from ZeroClaw's pairing flow, not from its config.

**Hermes Agent** has an A2A platform (`gateway.platforms.a2a` in `config.yaml`, with `A2A_BEARER_TOKEN` and `A2A_PUBLIC_URL` in `~/.hermes/.env`). We have not confirmed the exact path it serves, so read it from the bot's agent card at `https://your-bot.example.com/.well-known/agent-card.json`.

## Make a new key or remove a bot

- **New key** replaces the bot's key. The current key stops working within 30 seconds, and the new one is shown once, with the config filled in. Update the bot with it.
- **Remove** deletes the connection and revokes its key, which stops working within 30 seconds. The bot itself keeps running wherever you host it.
- **Edit** changes the name, the surfaces, the linked remote agent and the rate limit. Turning a surface off takes effect within 30 seconds.

## Limits and notes

- Everstack does not host or run the bot. It gives the bot a key and shows the config.
- Hosted bots such as Grok Bot and Meta Muse can use tools only. Grok Bot's docs do not document a static auth header for custom MCP servers, and Meta Muse connectors go through Meta's review.
- A rotated or removed key, or a surface you turned off, takes effect within 30 seconds, not instantly, because gateway replicas cache authenticated keys briefly. The replica that handled the change applies it at once.
- A bot over its rate limit gets HTTP 429 with a `Retry-After` header.
- Separately from any bot rate limit, the gateway limits every bot key by default to 300 requests a minute on `/mcp`, 600 a minute on OTLP ingest, and 60 a minute on the A2A server. Operators can change these.
- Per-bot spend budgets are not available yet.
- The Bots page needs dashboard sign-in. On Everstack Cloud that is your normal login. On a self-hosted gateway, turn sign-in on (`auth.mode: builtin`); with `auth.mode: none` the Bots and A2A admin pages answer 401.
- Trace and log ingest (`/v1/traces`, `/v1/logs`) is served only when the gateway has its ClickHouse telemetry store configured. Without it those endpoints return 404 for every caller.
- The agent call depth is limited: an agent reached through `run_agent` or A2A can start one more agent, and a third level is refused. This stops an agent whose tools point back at the same gateway from calling itself in a loop.
- The bot must support the setting shown. Where this guide lists plain values, check the bot's own documentation for where they go.
